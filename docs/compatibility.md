# crease/ui on hyper-effect: compatibility matrix

Generated by `npm run check:compat` from crease/ui's own component demos (121 components, every example). Each example is rendered through hyper-effect's server builder with Foldkit's markup validation on. Interactive examples also get one smoke interaction: the first clickable Message (or a typed value) is decoded, run through `update`, its Commands are tried, and the result is rendered again. Examples with keyboard handlers also get a keyboard pass: ArrowDown, ArrowDown, Enter and Escape, each on the first key handler that takes it, with `update` and the Commands run after every press (a Command that needs a browser on that path is listed under *skips*).

| Tier | Components | Meaning |
|---|---|---|
| Static | 19 | Renders on the server; binds no events. |
| Server-rendered, interactive | 31 | Renders on the server; its events become Messages on the server. |
| Server-side Submodel | 28 | A stateful component running on the server (Model, update, view); every interaction is a round trip. |
| Degraded | 42 | Works on the server, but a browser-only part is missing: an `OnMount` hook is dropped or a browser-only Command is skipped (focus, scrolling, positioning, dialogs). Fine where that part does not matter; otherwise use an island. |
| Island required | 0 | Uses an event the server cannot bind (file uploads). Run it as a Foldkit island. |
| Error | 1 | Does not render. |

Column notes: *drops* lists browser-only hooks removed on the server, *skips* lists browser-only Commands that fail on the server, and *forwards* lists Commands sent to the browser instead (client command forwarding).
